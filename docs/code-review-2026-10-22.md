# Ревью переноса Python → C++

Дата: 22 октября 2026. Проверены `bot_logic.py` и файлы `cpp/src/`. Ниже сохранены исходные замечания и статус их исправления. Изменения проверены в Chrome на локальном HTTP-сервере; публикации на реальных форумах для этой проверки не выполнялись.

Qt Widgets и WebDriver подходят для задачи. Разделены интерфейс, настройки и управление браузером; процесс драйвера освобождается через RAII, данные в JavaScript передаются отдельными аргументами, настройки сохраняются атомарно. После ревью подтверждение публикации вынесено в `ForumPage`, а общие модули собираются в библиотеку `prbot_core` для приложения и проверок.

## Выполненные исправления

- **Подтверждение отправок:** новый ID поста, автор, ссылки/изображения либо текст, обязательная точная ссылка на взаимность. Успех устанавливается после обеих проверок. Отказ и неопределённый результат останавливают проход без повторного клика.
- **Остановка и закрытие:** общий атомарный флаг, контроль между командами, завершение начатой пары отправок, отложенное закрытие окна и ожидание рабочего потока при уничтожении окна.
- **Поиск темы:** один обход сообщений на попытку входа; лишний переход в профиль удалён. Возможность второго PR-аккаунта сохранена.
- **Ожидания:** вместо фиксированных пауз проверяется готовность скрипта входа, данных аккаунта, поиска, темы и нового сообщения с ограничением времени.
- **Ошибки и порт:** ошибки WebDriver имеют вид и код; тайм-ауты не классифицируются по локализованному тексту. Для каждого драйвера выбирается свободный локальный порт.
- **Ссылки:** повторы проверяются по адресам из DOM, принадлежность шаблона — по URL из BBCode. Сравниваются полный хост, порт и граница каталога; короткое имя форума в произвольном тексте больше не принимается за ссылку.
- **История и предварительная проверка:** отдельный журнал каждого запуска в `logs/`, просмотр истории из окна и режим проверки до отправки рекламных сообщений.
- **Проверки:** добавлены локальные браузерные сценарии для успеха, отказов, частичного результата, PR-входа, пропуска партнёрки, остановки, закрытия окна и защиты от ложного подтверждения.

Остаются эвристики проверки рекламной темы, зависимость от разметки MyBB/RusFF и отсутствие автоматического возобновления частично выполненной пары. История хранит события и ссылки, но сама по себе не восстанавливает незавершённые публикации. Локальные проверки не заменяют проверку конкретного дизайна форума.

## Что даст ускорение

Основное время тратится на браузер, сеть и ожидания. Замена Python на C++ сама по себе не доказывает ускорение; сравнительного замера нет. Теперь удалены повторный поиск темы и обязательные паузы: на части форумов устранены дополнительное трёхсекундное ожидание и несколько переходов. Подтверждение отправок добавляет проверки DOM, поэтому общий выигрыш на реальных сайтах нужно измерять отдельно.

Публикации связаны: чужая реклама отправляется в исходную тему, а её ссылка — на целевой форум. Параллельный обход потребует отдельного управления этой последовательностью и общей исходной вкладкой.

## Предлагаемая структура рефакторинга

1. Оставить `WebDriverClient` транспортом, добавить ошибки с кодами и ожидания с ограничением времени.
2. Выделить адаптер MyBB/RusFF: PR-вход, поиск сообщений, выбор темы, извлечение шаблона и проверка нового поста. Селекторы сосредоточить здесь.
3. Вынести взаимную публикацию в отдельный сценарий со стадиями и сохранением частичного результата. Оркестратор прохода должен принимать готовый результат по каждому форуму.
4. Сохранить отдельные `BotWindow`, `BotConfig`, `RunLog`; проверять сценарии на локальных HTML-страницах и подставном WebDriver, включая отказ после первой отправки.

Полная перепись с нуля не обязательна. Полезнее последовательно переделать вход и подтверждение публикаций, сохраняя уже проверенное поведение поиска темы по сообщениям PR-аккаунта.
